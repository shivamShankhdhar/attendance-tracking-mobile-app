1. DEEP LINK ENTRY POINT  ✅ IMPLEMENTED
──────────────────────────────────────────────────────────────
  frontend/src/app/join/[token].tsx

  What it does:
    - Reads `token` from the dynamic route segment.
    - Calls savePendingJoin(token) to AsyncStorage immediately.
    - Sets ['pending-join'] in the React Query cache.
    - Calls router.replace('/join?token=<TOKEN>') so the user
      can't back-navigate into the raw /join/<TOKEN> URL.
    - Renders JoinWorkplaceRoute inline during the async save
      to avoid a blank flash.

  Why this matters:
    The token is now persisted to AsyncStorage BEFORE any
    sign-in redirect happens. When an unauthenticated user
    arrives via deep link → gets sent to / for Google sign-in
    → the token survives in storage → join.tsx picks it up
    via getPendingJoin() after sign-in completes.

USER-FACING FLOW (END-TO-END SUMMARY)
================================================================

ADMIN SIDE
──────────
  1. Admin opens Employer Dashboard → "Invite Members" card.
  2. App calls GET /:workplaceId/join-qr → gets invite token.
  3. Admin sees the invite link + Copy / Share / QR buttons.
  4. Admin shares the link via WhatsApp / Email / SMS / QR scan.
  5. Admin can tap "View Join Requests (N pending)" anytime →
     lands on /join-requests?workplaceId=<id>.
  6. Requests show with status badges:
       🟡 Pending  |  ✅ Approved  |  ❌ Rejected  |  🚫 Cancelled
  7. Admin taps a PENDING row → Approve or Reject dialog appears.
  8. On Approve: employee is added; push notification sent to employee.
  9. On Reject:  employee notified; reason stored and shown to employee.

EMPLOYEE SIDE
─────────────
  1. Employee receives invite link (e.g. https://bizora.app/join/xK9mP2qR).
  2a. App not installed:
       → Link opens App Store / Play Store.
       → Employee installs the app.
       → [Deferred deep link] app opens and recovers the token.
  2b. App installed:
       → Universal Link / App Link opens app directly.
       → Expo Router fires /join/[token].tsx.
       → Token saved to AsyncStorage (savePendingJoin).
       → Redirects to /join?token=<TOKEN>.
  3. If not signed in → redirected to / (sign-in screen).
       Token is preserved in AsyncStorage across sign-in.
  4. After Google sign-in → /join is re-entered with token from storage.
  5. Workplace Preview screen loads:
       ┌──────────────────────────────────────────────┐
       │  🏢 Acme Corp                                │
       │  "Track attendance effortlessly"             │
       │  👤 Admin:   John Doe                        │
       │  👥 Members: 24 active members               │
       │  📍 Mumbai, India                            │
       │                                              │
       │  Joining as Ravi Kumar (ravi@corp.com)       │
       │  [Note to admin (optional)]                  │
       │  [ Request to Join ]                         │
       └──────────────────────────────────────────────┘
  6. Employee taps "Request to Join".
     → POST /join-requests → requestId returned.
     → saveTrackedJoin(userId, { requestId, token }).
     → JoinStatusTracker replaces the form:

       ● Sent    ──●─────────────────────
       ● Pending ────────●───────────────
       ○ Decision ──────────────────○───

     → Polls every 5 s while PENDING.
     → "You can close the app — we'll update you when your admin responds."
  7. Employee can close the app and return later via:
       a. /my-join-requests → lists all their requests with status badges.
          Tapping "View details & status" re-opens the tracker on /join.
       b. Push notification (when admin acts).
       c. On app restart: startup check detects tracked join →
          shows banner or auto-opens if APPROVED.
  8. On APPROVED:
       → push notification + status updates to ✅.
       → join.tsx auto-calls openJoinedWorkplace().
       → Profile refreshed, membership selected, navigated to dashboard.
  9. On REJECTED:
       → push notification + status updates to ❌.
       → Rejection reason shown on tracker screen.
